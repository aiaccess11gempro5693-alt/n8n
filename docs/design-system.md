История и разбор референсов, из которых собрано предложение — в `docs/design-system-proposal.md` (черновик) и `docs/scenario-4-test-video.md` (первичная рабочая гипотеза для тестового сценария). Этот документ — итоговый, на него ориентируемся при генерации промптов/монтаже.

## 1. Палитра
- Фон: тёплый белый `#F7F9FB`
- Акцент 1: бирюзовый `#2A7F82`
- Акцент 2: коралловый `#F2836B`
- Текст: тёмно-серый `#2B2F33`

## 2. Типы сцен (Варианты 1/2/3, п.9 ТЗ)
- **Вариант 1 — полноэкранный аватар (16:9).** Только говорящая голова, без PIP.
- **Вариант 2 — полноэкранная инфографика + аватар в PIP.** Аватар — скруглённый прямоугольник ~18–20% ширины кадра, правый нижний угол, небольшой отступ от края.
- **Вариант 3 — полноэкранная иллюстрация + аватар в PIP.** Та же позиция/размер PIP, что в Варианте 2.

## 3. Субтитры (караоке, п.11 ТЗ)
- Плашка внизу кадра: фон тёплый белый `#F7F9FB`, текст `#2B2F33`, максимум 2 строки видимых одновременно.
- Караоке-подсветка произносимого слова — **коралловый `#F2836B`** (выбор Claude Code: контрастнее на светлой плашке с тёмным текстом, чем бирюзовый; бирюзовый остаётся для структурных акцентов — заголовки, PIP-рамка).
- Синхронизация по словам — генерируется монтажным кодом (ffmpeg/аналог), не отдельный сервис.
- **Субтитры — это ПОЛНАЯ дословная реплика диктора, целиком, во ВСЕХ сценах (включая инфографику/PIP-сцены), а не короткий пересказ.** (Уточнено 14.09.2026 по прямому замечанию — v12 показывал только короткую фразу-пересказ вместо полного текста, и не показывал субтитры вообще в сценах 3/5/6.) Длинная реплика режется на последовательные чанки по ≤2 строки, чанки сменяют друг друга по ходу ролика — это отдельная сущность от короткого "текста на экране" (п.4 ТЗ), которого это правило не касается.
- **Плашка субтитров — фиксированного размера и позиции на ВСЕХ сценах** (не подгоняется по ширине под конкретный текст). Причина: авто-подгонка ширины под текст (как было в v11/v12) даёт то один размер плашки, то другой от сцены к сцене — выглядит неаккуратно/"неровно". Фиксированная геометрия: слева от края с отступом, ширина не доходит до зоны PIP-аватара (чтобы никогда не перекрываться с ним), высота — под 2 строки.

## 4. Инфографика и иконки
- Плоские скруглённые карточки, outline-иконки, **без теней** (единый вариант — в черновике `scenario-4-test-video.md` было расхождение между сценами, здесь зафиксировано однозначно).
- Текст не рисуется на карточках — накладывается при монтаже (п.4 ТЗ), позиционируется фиксированными пиксельными координатами в монтажном коде поверх сгенерированной картинки.
- Появление карточек — прогрессивное, по одной, синхронно с озвучкой.
- **Промпт для многокарточных сцен (сетка/список из N карточек) должен явно задавать раскладку в процентах кадра** (например: "карточка 1 — x:5–45%, y:8–45% кадра; карточка 2 — x:55–95%, y:8–45%; ..."), а не только качественное описание ("аккуратная сетка 2×2"). (Причина, 14.09.2026: генерация без точных процентов дала картинку, где реальные позиции карточек разошлись с зашитыми в монтажный код пиксельными координатами подписей — подписи оказались "не там", см. лог в `CLAUDE.md`.) Координаты подписей в коде монтажа считаются от этих же процентов, не подбираются на глаз по одному сгенерированному примеру.

## 5. Заголовки / текст на экране
- Акцент — короткая цветная блок-плашка под текстом заголовка (акцентный цвет), не тонкая линия.
- **Шрифт: Inter** (выбор Claude Code — свободный, широко доступный sans-serif с полной поддержкой кириллицы, нейтральный современный вид, хорошо читается и в субтитрах, и в заголовках инфографики).

## 6. Фон вне карточек
- Сплошной тёплый белый или очень лёгкий градиент. Без волн/геометрических фигур на весь кадр.

## 7. Переходы (п.10 ТЗ)
- Спокойные: fade, лёгкое масштабирование, панорамирование.

## Если что-то из этого нужно поменять

Это утверждённая база, но не «высечено в камне» — если в процессе тестового рендера (например, по `docs/scenario-4-test-video.md`) что-то не будет смотреться, можно скорректировать точечно, не переделывая весь документ с нуля. Изменения — тем же циклом: предложение → утверждение.

## Подход B (эксперимент, 15.09.2026 — ещё не утверждён)

Пользователь предложил попробовать принципиально другую композицию сцены, чтобы сравнить:

- **Аватар всегда на весь кадр** — никогда не уменьшается в PIP-угол, даже в "инфографика"-сценах.
- **Не одна сплошная картинка-композиция на сцену, а несколько ОТДЕЛЬНЫХ маленьких иконок** — каждая генерируется как изолированный значок (например отдельно таблетка, отдельно градусник), а не как один цельный коллаж/сетка карточек.
- Эти отдельные иконки **накладываются поверх видео с аватаром, вокруг него** (не перекрывая лицо), с красиво оформленной подписью рядом с каждой — то есть иконки и текст становятся "плавающими" элементами вокруг говорящего, а не отдельным полноэкранным слайдом.
- Появление — по-прежнему прогрессивное, синхронно с озвучкой (как и в Подходе A).

Статус: **испытывается**, не утверждено. Технический вопрос решён и подтверждён рабочим — Nano Banana не даёт настоящую прозрачность через API, поэтому иконки генерируются на сплошном ярко-пурпурном фоне `#FF00FF` (промпт явно просит "БЕЗ карточки/рамки, только сама иконка на однотонном magenta-фоне") и вырезаются в ffmpeg через `colorkey=0xE91E8F:0.35:0.12` (реальный тон, который отдаёт модель, немного отличается от идеального `#FF00FF` из промпта — подобран эмпирически). Референс стиля для всех иконок — `scratch/icon-test-pillbottle.png` (первая проверенная иконка), это держит единый flat-outline-стиль по всей раскладке.

**Первая полная перегенерация ролика по Подходу B сделана — `scratch/scenario-4-test-video-v14-final.mp4`.** 11 отдельных изолированных иконок (по одной на сцену 2, по 4 на сцены 3/5, по 2 на сцену 6 — `scratch/scene{2,3,5,6}-icon*.png` + переиспользованная `icon-test-pillbottle.png`) наложены вокруг аватара (который теперь на весь кадр во всех 8 сценах без исключения) с подписями-чипами под каждой, появление каскадное (0.0/0.18/0.36/0.54с — те же тайминги, что были у чипов в Подходе A). Технический нюанс, на который наткнулись: иконка — это одиночный PNG-кадр без `-loop`, поэтому `fade`-фильтр по времени на нём не работает (кадр застревает на собственной t=0 и никогда не "доходит" до срабатывания fade) — появление сделано через `overlay=...:enable=gte(t,START)` (жёсткий поп-ин, как у текстовых чипов), без плавного fade-in.

Оба подхода (A и B) теперь имеют готовый отрендеренный референс (v13 и v14) — можно сравнивать визуально перед тем, как утверждать один из них как основной.

**Правка 15.09.2026 (v15, `scratch/scenario-4-test-video-v15-final.mp4`)** — по прямой жалобе "иконки не видно на фоне":
- Под каждой иконкой теперь **белая карточка-подложка** (`#F7F9FB`, простой прямоугольник с отступом 20px по каждой стороне) — рисуется как `drawbox` перед наложением иконки, тем же `enable=gte(t,START)`, что и сама иконка, так что появляются вместе. Без неё иконка (даже с ровным chromakey) плохо читалась на живом видео аптеки — недостаточно контраста.
- **Плашка субтитров теперь по центру экрана** (раньше была прижата влево — это было унаследовано от Подхода A, где место слева освобождалось под PIP-угол справа; в Подходе B PIP нет, поэтому центрировать было можно и нужно). `PANEL_X = (1920 - PANEL_W) / 2` в `compute_word_layout.py`.

**Правило 15.09.2026 (v16) — раскладка элементов должна отражать СМЫСЛОВУЮ структуру контента, не быть одним шаблоном "N штук — N углов" на все сцены.** Прямая жалоба: сцена 5 (чек-лист вопросов "что беспокоит / как давно / что принимаете / хронические болезни") использовала ту же 2×2-угловую раскладку, что и сцена 3 (4 НЕЗАВИСИМЫХ альтернативных варианта — "болеет каждую осень" ИЛИ "слабость после ОРВИ" ИЛИ...) — из-за этого чек-лист выглядел как 4 несвязанные картинки, а не как единый список. Правило на будущее, при выборе раскладки для N элементов сцены:
- **Последовательность / чек-лист / шаги** (пункты читаются друг за другом, как список) → **одна вертикальная колонка** (иконка слева от подписи в каждой строке, строки друг под другом), не раскидывать по разным углам/сторонам экрана.
- **Независимые / альтернативные варианты** (варианты "или"; порядок не важен, между собой не связаны) → сетка (2×2 и т.п.), каждый в своём углу — это ОК, раскладка честно показывает "это разные, несвязанные вещи".
- **Сравнение двух противоположностей** ("не то, а это") → пара слева/справа, друг напротив друга.
Сцена 3 (независимые причины) и сцена 6 (сравнение "излишне"/"нужно") уже соответствовали своей структуре и не менялись; сцена 5 переделана в вертикальный список — `scratch/scenario-4-test-video-v16-final.mp4`.

**Правка 15.09.2026 (v17) — иконки крупнее и ярче, по прямому запросу** ("давай будем делать более крупные яркие и читаемые значки но естественно не загораживая фармацевта"):
- Размер иконки/карточки увеличен в каждой сцене (сцена 2: 460→520px; сцена 3: 300→330px, из-за плотной 2-строчной раскладки по углам — самый скромный прирост из всех; сцена 5: 90→110px + расстояние между строками чек-листа увеличено со 150 до 170px; сцена 6: 420→470px). Рост всегда направлен ТОЛЬКО в сторону от аватара (к краю кадра) — сторона карточки, обращённая к аватару, зафиксирована по координате и не сдвигается при увеличении размера; там, где вырастающий внешний край мог упереться в правый край кадра (сцены 2/3/6), якорная x-координата сдвинута левее на ту же величину, чтобы карточка осталась в кадре с запасом ≥20–30px.
- Сама иконка после chromakey дополнительно проходит через `eq=saturation=1.4:contrast=1.1:brightness=0.03` — бирюзовые/коралловые линии стали заметно ярче/контрастнее на белой подложке (раньше выглядели немного блёкло на фоне живого видео). Белая карточка-подложка стала полностью непрозрачной (`@1.0`, было `@0.97`) для более чёткого контура. Цветные чипы подписи — тоже более насыщенные (`@0.95`, было `@0.88`).
- Подписи (шрифт/размер чипа) увеличены пропорционально новому размеру иконки в каждой сцене.
- Результат — `scratch/scenario-4-test-video-v17-final.mp4`. Проверено покадрово: иконки нигде не перекрывают фармацевта и не выходят за края кадра/плашку субтитров.

## Правило 15.09.2026 (v18): QA-вердикт при генерации — это ГЕЙТ, а не просто лог

Обнаружено при разборе жалобы "картинки не соответствуют подписям": у 8 из 11 сгенерированных иконок Gemini-проверка на шаге генерации (см. `call-image-pipeline.yml`) уже вернула **не-OK вердикт** (смысловое противоречие реплике и/или заметный артефакт генерации), но изображение всё равно попадало в монтаж — потому что вердикт только сохранялся в JSON рядом с картинкой, и НИКТО его не читал перед использованием файла. Ровно тот пробел, что уже отмечен в ТЗ (`CLAUDE.md`, статус по п.7: "проверяет качество... но НЕ перегенерирует автоматически при ошибке — просто возвращает вердикт").

**Правило на будущее, обязательное для любого нового ассета (иконка/подложка/инфографика), не только для этого тестового ролика:** прежде чем использовать сгенерированный файл в монтаже, `verdict` из соответствующего `.json` должен быть прочитан. Если вердикт НЕ начинается с "OK" — ассет не идёт в монтаж как есть, а либо (а) перегенерируется с промптом, точечно исправляющим то, что назвал вердикт (не общий повтор промпта — конкретная правка под конкретную причину), либо (б) человеку явно показывается, что ассет не прошёл проверку, и запрашивается решение. Молчаливое использование не-OK ассета — баг.

## Правило 15.09.2026 (v18): ничего не размещать в углах кадра

По прямой жалобе — счётчик сцены "NN/08" в левом нижнем углу убран полностью. **Правило на будущее:** никакие служебные элементы (счётчики, даты, бейджи, водяные знаки и т.п.) не размещаются ни в одном из четырёх углов кадра — ни сейчас, ни в будущих версиях. Прогресс-бар по сценам (полноширинная полоса снизу, не привязанная к конкретному углу) — не подпадает под это правило и остаётся.

## Правка 15.09.2026 (v18): текст субтитров — по-настоящему по центру плашки

Раньше (v15) центрировали только САМУ плашку на экране, но текст внутри неё оставался прижат к левому краю плашки (артефакт технической реализации — единый multiline `drawtext` с фиксированным `x`, без built-in центрирования строк разной длины). По прямой жалобе исправлено: каждая строка чанка теперь рендерится ОТДЕЛЬНЫМ `drawtext`-вызовом со своим вычисленным `x`, центрирующим именно эту строку в границах плашки (`compute_word_layout.py`/`caption_filter.py`). Коралловая crop-подсветка слова использует те же центрированные координаты, поэтому подсветка по-прежнему совпадает пиксель-в-пиксель с серым текстом под ней.
