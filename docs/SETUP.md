# Настройка: n8n как набор "воркеров" для Claude Code

## Архитектура (важно понимать, прежде чем настраивать)

n8n здесь — **не один автоматический пайплайн**, а набор из **4 независимых воркеров** (каждый — свой Webhook-адрес). Вся "умная" часть — диалог с человеком, решения ok/не-ок, финальный монтаж видео — происходит **снаружи n8n**, в чате с Claude Code. Claude Code дёргает эти воркеры по отдельности, в том порядке, который нужен, и сам решает, что делать с результатом.

**Кто что делает:**

- **Claude Code** — пишет сценарий, раздаёт задачи ElevenLabs/Heygen/Nano Banana, спрашивает у человека ok/не-ок, при "не ок" отправляет конкретный кусок на переделку, в конце сам делает монтаж видео и субтитры.
- **Gemini** — дешёвая механическая часть: дорабатывает описание сцены в детальный промпт для рендера + проверяет качество готовой картинки. Где ещё можно дёшево переложить работу на Gemini (например, часть монтажных решений) — тоже отдаём ему.
- **Nano Banana** (модель изображений Gemini) — сам рендер картинки по промпту.
- **ElevenLabs** — озвучка текста.
- **Heygen** — аватар (важная часть сценария, не просто "слой поверх").

Публикация (VK/Instagram/сайт) и интерфейс — сознательно не делаем сейчас, вернёмся позже.

**4 воркера в n8n:**

| Адрес | Метод | Что делает |
|---|---|---|
| `/tts` | POST | Озвучка текста (ElevenLabs) |
| `/image` | POST | Промпт (Gemini) → картинка (Nano Banana) → проверка качества (Gemini) |
| `/avatar-start` | POST | Запускает генерацию аватара в Heygen, сразу возвращает `video_id` (само видео ещё не готово) |
| `/avatar-status` | GET | Проверяет по `video_id`, готово ли видео с аватаром |

Аватар у Heygen генерируется не мгновенно (может занять пару минут), поэтому это два отдельных адреса: один запускает генерацию, второй — можно опрашивать раз в 10–15 секунд, пока не будет готово.

Везде, где написано "сделай сам" — шаги, которые нужно выполнить руками (регистрации, ключи). Всё остальное уже готово в файле `workflows/mvp-content-pipeline.json`.

## Шаг 1. Завести n8n Cloud

1. Открой https://n8n.io и нажми **Get started free** (или **Start for free**).
2. Зарегистрируйся (email или Google-аккаунт).
3. При создании инстанса выбери регион (любой ближайший, например Europe).
4. После создания откроется редактор n8n.

## Шаг 2. ElevenLabs — озвучка

1. Открой https://elevenlabs.io и зарегистрируйся (есть бесплатный тариф с ограниченным числом символов в месяц).
2. Профиль (иконка справа вверху) → **API Keys** → скопируй ключ.
3. (Опционально) **Voice Library** → выбери голос → **Copy Voice ID**. По умолчанию в воркфлоу стоит готовый голос "Rachel" (`21m00Tcm4TlvDq8ikWAM`).

## Шаг 3. CometAPI — Gemini (промпты + проверка качества) и Nano Banana (картинки)

Используем не напрямую Google AI Studio, а прокси-сервис **CometAPI** (`api.cometapi.com`) — он даёт доступ к тем же моделям Gemini/Nano Banana дешевле и без требования включённого биллинга на Google-аккаунте (у Google на бесплатном тарифе нет квоты на генерацию картинок вообще, `limit: 0` — проверено на практике 04.08.2026).

1. Открой https://www.cometapi.com и зарегистрируйся.
2. В личном кабинете найди раздел API-ключей и создай ключ.
3. Один ключ используется для трёх вещей: доработка промптов, генерация картинок (Nano Banana), проверка качества — регистрировать отдельно ничего не нужно.
4. CometAPI повторяет формат самого Gemini API один в один — меняется только базовый адрес (`generativelanguage.googleapis.com` → `api.cometapi.com`) и заголовок аутентификации `x-goog-api-key` (значение — ключ CometAPI, а не Google). В `workflows/mvp-content-pipeline.json` это уже учтено.

## Шаг 4. HeyGen — аватар

1. Открой https://www.heygen.com и зарегистрируйся.
2. Найди в настройках аккаунта раздел API / API Keys (обычно в Settings → API) и создай/скопируй ключ.
3. Тебе понадобятся ещё `avatar_id` и `voice_id`. По решению Олега рендер идёт движком **Avatar III** — он применяется к своим Photo Avatar (аккаунт → загруженные фото), а не к аватарам из общей публичной библиотеки. Если в интерфейсе HeyGen не сразу видно ID, их можно получить запросом к API (например, через браузер, Postman или curl) с твоим ключом в заголовке `X-Api-Key`:
   - Список своих Photo Avatar: `GET https://api.heygen.com/v3/avatars`
   - Список голосов: `GET https://api.heygen.com/v2/voices`
   - (Список публичной библиотеки аватаров, для справки: `GET https://api.heygen.com/v2/avatars`)
   В ответе найди нужный аватар/голос и скопируй его `avatar_id` / `voice_id`.

## Шаг 5. Создать credentials в n8n

**Settings** (шестерёнка внизу слева) → **Credentials** → **Add Credential**. Нужно создать три штуки, все типа **Header Auth**:

| Название credential (важно называть именно так) | Header Name | Header Value |
|---|---|---|
| `ElevenLabs API` | `xi-api-key` | твой ключ из ElevenLabs |
| `CometAPI (Gemini)` | `x-goog-api-key` | твой ключ из CometAPI |
| `HeyGen API` | `X-Api-Key` | твой ключ из HeyGen |

Для каждой: **Add Credential** → в поиске выбери **Header Auth** → впиши имя → впиши Header Name и Header Value → **Save**.

## Шаг 6. Импортировать воркфлоу

1. В n8n слева **Workflows** → **Add workflow** → сверху справа троеточие (**...**) → **Import from File**.
2. Выбери файл `workflows/mvp-content-pipeline.json` из этого репозитория.
3. Воркфлоу откроется в редакторе со всеми нодами (сгруппированы по 4 воркерам сверху вниз).

## Шаг 7. Привязать credentials к нодам

После импорта credentials нужно перевыбрать вручную (их ID не совпадают между аккаунтами):

- **"Озвучка (ElevenLabs)"** → `ElevenLabs API`
- **"Уточнить промпт (Gemini)"**, **"Картинка (Nano Banana)"**, **"Проверка качества (Gemini)"** → `CometAPI (Gemini)`
- **"Создать видео (Heygen)"**, **"Проверить статус (Heygen)"** → `HeyGen API`

## Шаг 8. Активировать воркфлоу и собрать адреса

1. В правом верхнем углу редактора включи **Active**.
2. По очереди открой все 4 ноды **Webhook: /tts**, **/image**, **/avatar-start**, **/avatar-status** и скопируй у каждой **Production URL**.
3. **Пришли все 4 адреса мне (Claude Code) в чат.** Дальше, когда попросишь сделать видео, я сам буду вызывать нужные адреса в нужном порядке.

## Формат запросов и ответов

**POST /tts**
```json
{ "text": "текст для озвучки", "voice_id": "необязательно" }
```
Ответ: mp3-файл напрямую в теле ответа.

**POST /image**
```json
{ "scene_description": "краткое описание сцены" }
```
Ответ:
```json
{
  "prompt": "детальный промпт, который использовался",
  "image_base64": "...",
  "mime_type": "image/png",
  "verdict": "OK или описание проблемы"
}
```

**POST /avatar-start**
```json
{ "script": "текст, который скажет аватар", "avatar_id": "...", "voice_id": "..." }
```
Ответ: `{ "video_id": "..." }` — видео ещё генерируется.

**GET /avatar-status?video_id=...**
Ответ:
```json
{ "status": "processing" | "completed" | "failed", "video_url": "...", "error": null }
```

## Шаг 9. Тестовый запуск

Как только пришлёшь мне 4 адреса — просто напиши, например: *"сделай видео про то, почему кошки любят коробки"*. Я разложу задачу на вызовы этих воркеров, покажу тебе промежуточные результаты (озвучка/картинки/аватар) для проверки ok/не-ок, и после одобрения сам соберу финальное видео.

Если что-то не работает — открой **Executions** в n8n слева, там видно, на каком шаге ошибка (обычно неправильный credential или неверный ключ).
