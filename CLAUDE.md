# Правила работы над проектом (для Claude)

## Главный чат / ветвление

Этот чат — основной, корневой чат проекта. Именно в нём хранится весь контекст: что уже сделано, какие решения приняты, какие есть договорённости с пользователем.

Если в рамках работы возникает крупная подзадача, которую разумнее делать в отдельном новом чате (например, чтобы не перегружать контекст текущего чата), Claude должен:

1. **Явно сказать об этом пользователю** — не создавать новый чат молча и не предполагать, что пользователь сам догадается.
2. **Подготовить и передать сводку контекста**, достаточную для старта работы в новом чате: что за подзадача, зачем она нужна, что уже сделано по ней здесь, какие файлы/пути/коммиты/ссылки относятся к делу, какие решения уже приняты и какие ограничения есть.
3. Дать пользователю на выбор: продолжить здесь или открыть новый чат с этой сводкой — **решение и фактическое открытие нового чата всегда за пользователем**, Claude сам новые чаты не инициирует.

## Общий контекст проекта

Проект: автоматизированный пайплайн генерации контента. **Важная архитектурная договорённость: n8n — это НЕ один автопайплайн, а набор независимых "воркеров" (Webhook-адресов).** Вся оркестрация (диалог с человеком, ok/не-ок по каждому куску, финальный монтаж видео) происходит СНАРУЖИ n8n — в чате с Claude Code, который дёргает воркеры по отдельности и сам решает, что делать дальше. Где именно физически будет жить этот "оркестрирующий" чат/проект — пока не решено, это не важно на данном этапе.

**Роли (важно не путать):**
- Claude Code — сложная творческая часть: сценарий + черновые описания сцен, раздача задач сервисам, диалог с человеком (ok/не-ок), финальный монтаж видео и субтитры.
- Gemini — дешёвая механическая часть: доработка черновых описаний в детальные промпты для рендера + проверка качества готовых картинок (это "оркестрация", а не рендер). При монтаже — тоже отдавать Gemini всё, что можно сделать дёшево.
- Nano Banana (модель изображений Gemini) — сам рендер картинки по промпту. Отдельная роль от Gemini-оркестрации выше, хоть провайдер один.

Сквозной сценарий работы:
1. Человек ставит задачу Claude Code.
2. Claude Code пишет сценарий, параллельно раздаёт задачи ElevenLabs (озвучка), Heygen (аватар), Nano Banana (картинки, через Gemini-промпты).
3. Сервисы возвращают результат Claude Code.
4. Claude Code показывает результат человеку: ok/не-ок по каждому куску. Не ок → тот кусок уходит на переделку в свой сервис. Ок → дальше.
5. Claude Code сам монтирует финальное видео (субтитры, склейка, аудио), частично привлекая Gemini для экономии.
6. Финальная проверка → результат человеку.
7. Публикация (VK/Instagram/сайт) — сознательно вне скоупа сейчас, вернёмся позже. Интерфейс — тоже потом.

Полный план (не терять ни один пункт при дальнейшей работе):

1. Сценарий + черновые описания сцен — Claude Code, без отдельного API-ключа.
2. Доработка промптов + проверка качества картинок — Gemini.
3. Рендер картинок — Nano Banana.
4. Озвучка — ElevenLabs.
5. **Аватар — Heygen.** (легко забыть/потерять из виду — держать в плане явно)
6. Монтаж видео — субтитры, склейка картинок/видео, вставка аудио. Делает Claude Code сам (не n8n).
7. Публикация — VK, Instagram, сайт + хранилище контента. (отложено)

n8n (готово) — это 4 независимых воркера: `/tts`, `/image`, `/avatar-start`, `/avatar-status`, покрывающих пункты 2–5. См. `docs/SETUP.md` и `workflows/`.
